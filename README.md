# CS-230 Portfolio

This repository contains my software design document for The Gaming Room from my CS-230 Operating Platforms course.

### Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

The Gaming Room was the client, they wanted to expand their existing Android game "Draw It or Lose It", into a web-based application. The software needed to allow the game to be accessed from different devices and operating systems by multiple players at once.

### What did you do particularly well in developing this documentation?

I did a good job comparing the different operating systems and figuring out which ones would work best for the game. I also made sure to keep the requirements of the game in mind when making my recommendations.

### What about the process of working through a design document did you find helpful when developing the code?

The design document helped me understand what was expected of me before working on any code. Breaking everything down beforehand made it much easier to see how each part of the application contributes to the final product.

### If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would go back and add more detail to some of my earlier recommendations. As the course went on, I understood the different operating systems better and could explain why certain choices made more sense.

### How did you interpret the user's needs and implement them into your software design? Why is it so important to consider the user's needs when designing?

I focused on what The Gaming Room needed from the application, especially being able to support multiple users and different platforms. Keeping the user's needs in mind is important because there is no point in designing something that no one intends to use or needs.

### How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

I approached the design by breaking the requirements into smaller goals and working through them one at a time. I would probably use the same approach in the future because it makes a larger project feel more manageable.
